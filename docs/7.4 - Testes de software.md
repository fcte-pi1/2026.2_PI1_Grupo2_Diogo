## Disponibilidade da telemetria — RNF-SW04 / issue #45

Os testes de `src/backend/tests/test_telemetry_availability.py` exercitam a API
HTTP e os dois WebSockets com o cliente FastAPI e um banco simulado. Cobrem
recepção antes da corrida, preservação dos dados após perda de sinal, retorno
dos pacotes, falha de leitura/gravação no banco, amostras fora de ordem e
reconexão de assinantes. Os testes de serviço verificam a idade da amostra
separadamente da idade do último pacote recebido.

No frontend, `src/contexts/TelemetryProvider.test.tsx` cobre a conexão
compartilhada, reconexão com espera crescente, silêncio do servidor, mensagens
inválidas, preservação das leituras e limpeza dos temporizadores. O cenário de
dez minutos usa relógio simulado. `src/pages/TelemetryPage.test.tsx` verifica os
avisos, os últimos valores exibidos e o início da primeira corrida sem histórico.

Para executar, em `src/backend`:

```powershell
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pytest -q tests/test_telemetry_service.py tests/test_telemetry_routes.py tests/test_telemetry_availability.py
```

Em `src/frontend/web-micromouse`:

```powershell
npm.cmd ci
npm.cmd run test:unit
npm.cmd run build
```

O teste de navegador `src/frontend/web-micromouse/e2e/telemetry.spec.ts`
automatiza a espera por dados, o início da primeira corrida, o aviso de perda
de conexão e a retomada sem recarregar a página. As respostas HTTP e os pacotes
WebSocket são simulados pelo Playwright; esse teste não usa a ESP nem o banco.

```powershell
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

RNF-SW04-T01 (5–10 minutos), incluindo queda de Wi-Fi e retorno dos dados, ainda
precisam ser realizados. Os testes descritos acima não comprovam a cobertura
global mínima de 80%.
